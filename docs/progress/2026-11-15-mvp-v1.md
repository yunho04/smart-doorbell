# MVP v1 Backend / Database Progress

## 1. MVP v1 목표

MVP v1의 목표는 Raspberry Pi, Spring Boot, AI Server, PostgreSQL 간의 전체 통신 흐름을 연결하여 하나의 방문 Event가 처음부터 끝까지 처리되는 것을 확인하는 것이다.

현재 단계에서는 기능의 완성도보다 각 모듈 간 End-to-End 연결을 우선한다.

## 2. 전체 처리 흐름

1. Raspberry Pi에서 센서 이벤트를 감지한다.
2. 센서 이벤트를 MQTT/Mosquitto를 통해 Spring Boot로 전달한다.
3. Spring Boot는 새로운 Event를 생성하고 Event ID를 발급한다.
4. Raspberry Pi는 이미지 데이터를 Vision 서버로, 음성 데이터를 STT 서버로 전달한다.
5. Vision 분석 결과와 STT 전사 결과는 LLM으로 전달된다.
6. LLM은 방문 상황을 종합하여 위험도, 상황 요약, 응답 메시지를 결정한다.
7. LLM은 선택한 응답을 Raspberry Pi에 직접 전달한다.
8. Raspberry Pi는 전달받은 응답 메시지를 재생한다.
9. LLM은 동시에 위험도, 요약, 선택한 응답 정보를 Spring Boot로 전달한다.
10. Spring Boot는 해당 결과를 Event ID를 기준으로 PostgreSQL에 저장한다.

## 3. 응답 처리 방식 변경

기존 설계에서는 Spring Boot가 사전에 정의된 응답을 선택하여 Raspberry Pi에 전달하는 방식을 고려하였다.

현재 설계에서는 LLM이 사전에 정의된 응답 목록 중 상황에 적합한 응답을 직접 선택하고 Raspberry Pi에 전달한다.

따라서 Spring Boot는 응답을 결정하거나 Raspberry Pi에 전달하지 않는다.

Spring Boot는 LLM으로부터 다음 최종 결과를 전달받아 저장하는 역할을 담당한다.

- 최종 위험도
- 상황 요약
- 선택된 응답 코드
- 실제 응답 내용

## 4. MVP v1 Database

현재 MVP v1에서는 구현에 필요한 최소 데이터만 관리하기 위해 다음 세 개의 테이블을 우선 구성하였다.

### DEVICES

Raspberry Pi 기반 스마트 도어벨 장치 정보를 관리한다.

주요 속성:

- device_id
- device_name
- status
- created_at

### EVENTS

한 번의 방문 상황 전체를 관리하는 핵심 테이블이다.

주요 속성:

- event_id
- device_id
- status
- started_at
- ended_at
- risk_level
- summary
- response_code
- response_text
- created_at
- updated_at

### MEDIA_FILES

Event와 관련된 이미지 등의 파일 위치를 관리한다.

실제 이미지 파일 자체는 PostgreSQL에 저장하지 않고 File Storage에 저장하며, 데이터베이스에는 해당 파일의 경로만 저장한다.

주요 속성:

- media_id
- event_id
- media_type
- file_path
- created_at

관계는 다음과 같다.

DEVICES 1 : N EVENTS

EVENTS 1 : N MEDIA_FILES

## 5. Dashboard에 제공할 MVP 데이터

Dashboard에서는 Event를 기준으로 다음 정보를 제공할 예정이다.

- Event ID
- 대표 방문자 이미지
- Event 시작 시간
- Event 종료 시간
- 최종 위험도
- 상황 요약
- 시스템이 방문자에게 응답한 내용

device_id는 내부 데이터 연결을 위해 유지하지만, MVP 시연에서는 단일 장치를 사용하므로 사용자 화면에 반드시 표시할 필요는 없다.

## 7. MVP v1 완료 기준

다음 흐름이 실제 환경에서 한 번 이상 정상적으로 동작하면 MVP v1을 완료한 것으로 판단한다.

Raspberry Pi 센서 감지  
→ MQTT  
→ Spring Boot Event 생성  
→ Raspberry Pi 이미지 / 음성 전달  
→ Vision / STT / LLM 분석  
→ LLM 응답 결정 및 Raspberry Pi 전달  
→ LLM 최종 결과 Spring Boot 전달  
→ PostgreSQL 저장

MVP v1 완료 이후 사용자 인증, 세부 센서 로그, Vision 분석 이력, 알림, 사용자 피드백, RAG 고도화 및 Dashboard 기능을 단계적으로 추가한다.
